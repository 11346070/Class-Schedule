## 備用情境

### 如果遇到問題

#### 情境一：伺服器無法啟動
**處理方式：**
1. 檢查虛擬環境是否啟動
2. 執行 `python manage.py check`
3. 檢查 `.env` 檔案是否存在
4. 重新安裝依賴：`pip install -r requirements.txt`

#### 情境二：選課失敗
**處理方式：**
1. 重新整理頁面
2. 檢查課程是否已選過
3. 檢查課程是否額滿
4. 檢查是否有時間衝突

#### 情境三：畫面跑版
**處理方式：**
1. 清除瀏覽器快取
2. 重新整理頁面
3. 確認靜態檔案路徑正確

#### 情境四：資料異常
**處理方式：**
1. 重新啟動伺服器（資料會重置）
2. 重新選課

## 提問準備

### 可能的提問與回答

**Q1：為什麼不使用資料庫？**
> A：這是專題的明確要求，目的是讓我們專注在業務邏輯與系統架構，而非資料庫操作。採用記憶體儲存也有其優點，例如存取速度快、部署簡單，適合課堂展示與小規模應用。

**Q2：重啟後資料會消失，這樣合理嗎？**
> A：這是記憶體儲存的已知限制。在實際應用中，可以加入資料庫或檔案序列化來解決。但對於課堂展示與測試環境，這個限制是可接受的。每次重啟都會載入預設的示範資料，方便重複展示。

**Q3：如何確保名額不會被重複占用？**
> A：系統使用了單例模式（Singleton Pattern）確保所有請求共用同一份課程資料，並使用 threading.Lock 防止並發問題。選課與退選操作都會加鎖，確保名額更新的原子性。

**Q4：如何防止一個人選同一門課兩次？**
> A：選課前會檢查該使用者是否已選過此課程。使用者的選課清單用 Python Set 儲存，天生不允許重複元素。

**Q5：如何識別不同使用者？**
> A：使用 Django Session Key 作為使用者 ID。每個瀏覽器 Session 視為一位獨立使用者。Session 資料儲存在檔案系統中（sessions/ 目錄），不依賴資料庫。

**Q6：課程衝突是如何判斷的？**
> A：首先檢查是否為同一星期，然後檢查節次是否重疊。節次重疊使用區間重疊演算法：只要不符合「end1 < start2 或 end2 < start1」就表示重疊。

**Q7：學分上限是如何設定的？**
> A：系統預設學分上限為 25 學分，這是示範用途的合理值。使用者可以根據需求調整上限，系統會在選課時檢查是否超過限制。

**Q8：收藏功能和選課有什麼差別？**
> A：收藏功能不會占用課程名額，只是將課程加入候選清單。使用者可以先收藏感興趣的課程，之後再正式選課。

**Q9：系統如何支援行動裝置？**
> A：系統採用 RWD 響應式設計，使用 CSS Grid 與 media queries 針對不同螢幕尺寸調整版面。導覽列在手機版會變為漢堡選單，支援 Escape 鍵關閉及 ARIA 無障礙屬性。課程篩選表單在手機版採用優化的 Grid 排列，避免過度垂直延伸。課表在小螢幕上可以水平捲動，確保資訊完整顯示。

**Q10：系統可以支援多少使用者？**
> A：理論上取決於伺服器記憶體大小。但因為採用單程序執行，建議不超過 100 位並發使用者。對於課堂展示與小規模選課系統已經足夠。

**Q11：如果要擴充到正式環境，需要改什麼？**
> A：主要需要加入資料庫（如 PostgreSQL）、改用 Django ORM、加入使用者認證系統、使用分散式快取（如 Redis）處理並發、加入更完善的錯誤處理與日誌記錄，以及部署到生產環境的 Web 伺服器（如 Nginx + Gunicorn）。
